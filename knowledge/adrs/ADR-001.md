# ADR-001: Duy Trì 1 Collection Vector Duy Nhất Phân Vùng Bằng Hierarchical Payload Filter

## Bối cảnh (Context)
Khi kho tri thức mở rộng từ tài liệu đặc tả (Specs) sang bộ nhớ dài hạn của Agent (ADRs, Gotchas, Golden Exemplars), nảy sinh câu hỏi kiến trúc:
- *Phương án A:* Chia tách vật lý thành nhiều collection trong Qdrant (`specs_collection`, `gotchas_collection`, `exemplars_collection`).
- *Phương án B:* Duy trì 1 collection duy nhất (`sdd_specs`) và phân vùng logic bằng trường payload (`project_id`, `memory_tier`, `item_type`, `valid_to`).

## Quyết định Kiến trúc (Decision)
Chúng tôi quyết định chọn **Phương án B: Duy trì 1 Collection duy nhất kết hợp Hierarchical Payload Filter**.

## Lý do Kỹ thuật (Rationale)
1. **Đồng nhất Không gian Vector (Unified Metric Space):** Toàn bộ dữ liệu đều dùng chung mô hình embedding đa ngữ `bge-m3` (1024 dims). Nằm chung trong 1 collection đảm bảo điểm Cosine Similarity phản ánh công bằng, không bị lệch phân phối điểm (score drift) giữa các collection riêng biệt.
2. **Hiệu năng Qdrant ACORN / Filtered HNSW cực nhanh:** Qdrant hỗ trợ lọc payload trực tiếp trong quá trình duyệt đồ thị vector với độ trễ dưới 1 mili-giây.
3. **Giảm thiểu Network Roundtrips:** Khi Agent cần truy hồi đồng thời cả Spec lẫn Ràng buộc cấm kỵ, chỉ cần 1 API request duy nhất thay vì 3-4 request song song kèm thuật toán merge thủ công phức tạp ở backend.

## Hậu quả & Đánh đổi (Consequences)
- **Tích cực:** Quản lý vòng đời dữ liệu tinh gọn; dễ dàng mở rộng thêm các tầng trí nhớ mới chỉ bằng cách thêm giá trị enum vào payload.
- **Tiêu cực / Rủi ro:** Cần đảm bảo index payload trường `project_id`, `memory_tier`, `valid_to` luôn được tạo sẵn sàng lúc khởi tạo collection.

## Cập nhật 2026-10-25: Hiện thực trên PostgreSQL

Quyết định vẫn giữ nguyên (một kho vector chung, phân vùng bằng trường lọc); chỉ phần hiện thực đã đổi theo Quyết định B4 (CYBEROS-01 §3.1): Qdrant được thay bằng PostgreSQL 17 + pgvector.

- Kho chung là bảng `chunks` duy nhất, lọc theo `project_id` (không phân biệt hoa thường) và `valid_to IS NULL` ngay trong lượt quét HNSW (`hnsw.iterative_scan = relaxed_order`, `ef_search = 100`).
- Lý do số 2 (Qdrant ACORN / Filtered HNSW) chỉ còn giá trị lịch sử; pgvector đảm nhận vai trò lọc trong khi quét.
- `memory_tier` và `item_type` không phải cột của `chunks`: chúng nằm trong frontmatter của spec và được đọc từ bảng `documents` (ví dụ `recall_guardrails`).

# ADR-002: Tách Biệt Giao Thức Kép (MCP stdio cho Agent vs REST SSE cho Con Người)

## Bối cảnh (Context)
Hệ thống Personal-KB có 2 đối tượng sử dụng với nhu cầu hoàn toàn trái ngược:
1. **AI Agents (Cursor, Claude Desktop, Antigravity, Kiro, Codex):** Cần giao tiếp máy-với-máy (M2M) cực nhanh, không qua UI, tuân thủ chặt chẽ chuẩn Model Context Protocol (MCP), yêu cầu stdout 100% sạch cho JSON-RPC framing.
2. **Con người (Software Engineer, Reviewer, Business Analyst):** Cần giao diện Web Dashboard trực quan, xem tài liệu, duyệt đề xuất (`/approvals`), chat streaming thời gian thực qua Server-Sent Events (SSE) kèm huy hiệu trích dẫn (Citation Badges).

## Quyết định Kiến trúc (Decision)
Chúng tôi quyết định triển khai **Kiến trúc Giao thức Kép (Dual-Protocol Architecture)**:
- **Agent Protocol:** Chuẩn MCP Server chạy qua `stdio` transport (`python -m personal_kb.mcp.cli`), tích hợp trực tiếp vào config JSON của Agent CLI / IDE.
- **Human Protocol:** REST API + SSE Streaming trên FastAPI (`/api/v1/chat`, `/api/v1/specs`, `/api/v1/proposals`), phục vụ trực tiếp Frontend Next.js.

## Lý do Kỹ thuật (Rationale)
1. **Zero Contamination:** Không bao giờ trộn lẫn logic format chat của người dùng (như avatar, typing bubble, HTML citations) vào luồng context sạch của Agent.
2. **Khả năng tương thích tuyệt đối:** Mọi Agent hiện đại trên thị trường đều hỗ trợ native MCP stdio.
3. **Bảo toàn giao diện Web:** Frontend Next.js không cần viết lại để tương thích với cơ chế framing phức tạp của MCP.

## Hậu quả & Đánh đổi (Consequences)
- **Tích cực:** Độ độc lập cao; có thể nâng cấp engine MCP mà không làm đứt kết nối của Web Dashboard và ngược lại.
- **Tiêu cực:** Cần duy trì song song 2 tầng API (MCP tool definitions và REST endpoints).

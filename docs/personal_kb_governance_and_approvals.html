🎨 1. Dọn Sạch Thương Hiệu "Personal KB"

Đã loại bỏ hoàn toàn các chuỗi CyberOS trên giao diện người dùng:

  • Page Title & Description: Đổi thành Personal KB | Knowledge Base (layout.tsx).
  • Giao diện Chat & Header: Đổi tên và logo sang Personal KB (c/layout.tsx, sidebar.tsx).
  • Trang Đăng Nhập: Đổi sang Personal KB - Quản trị kho tri thức (login/page.tsx).
  • Package Name: Đổi thành personal-kb-chat (package.json).
  • Backward Compatibility: Hỗ trợ token key mới personalkb.devToken cùng fallback cyberos.devToken, export alias CyberosChatTransport.
🛡️ 2. Trang Phê Duyệt Tri Thức (/approvals)

Cổng kiểm duyệt và quản trị tài liệu trực quan:

  • Dashboard Thống kê: 4 Metric Cards (Tổng đề xuất, Chờ duyệt Pending, Đã duyệt Approved, Đã từ chối Rejected).
  • Sidebar Integration: Tích hợp link "Phê duyệt tri thức" trên Sidebar kèm Badge đếm số lượng đề xuất Chờ duyệt.
  • Chi Tiết & Preview Markdown: Modal hiển thị lý do đề xuất (Rationale) và render Markdown nguyên văn đề xuất.
  • Nút Hành Động: Phê duyệt 1 chạm (tự động re-ingest và đóng chunk cũ) hoặc Từ chối (nhập lý do phản hồi).
  • Tự Tạo Đề Xuất: Modal cho phép người dùng tự gửi proposal cập nhật tri thức mới.
⚙️ 3. Cơ Chế Proposal Store & Dual Protocol Tích Hợp

AI Agent không thể tự ý ghi đè vào file spec gốc. Khi phát hiện thông tin lỗi thời hoặc người dùng cung cấp thông tin mới, Agent sẽ gọi tool để tạo proposal ở trạng thái PENDING.

🤖 Agent Tool (Dual-Channel)

Agent nội bộ: propose_kb_update
MCP Server: propose_knowledge_update
Đầy đủ tham số: spec_id, title, proposed_content, rationale, section.

🔒 An Toàn & OCC (Concurrency)

Lưu trữ file JSON tại knowledge/proposals/*.json. Hàm resolve_spec_path chống Path Traversal và kiểm soát SHA-256 hash (OCC) ngăn chặn Lost Update.

⚡ Tự Động Re-ingest Khi Approve

Khi duyệt đề xuất, backend cập nhật file Markdown spec, đóng chunk cũ (valid_to = now()) và nhúng chunk mới vào pgvector ngay lập tức không cần restart server.

Việc thay thế phải được thực hiện bằng cách hấp thụ (absorb) cơ chế AST Parsing (Tree-sitter) & Relational Call-Graph của CodeGraph trở thành một Subsystem chuẩn bên trong kiến trúc Memory Fabric (CYBEROS-01 / PKB-02).

Sai Lầm Phổ Biến
Dùng Vector RAG thay AST

Vector search mang tính xác suất (probabilistic), không thể cam kết 100% tìm đúng toàn bộ Callers/Callees của một hàm và làm bùng nổ token.

Thực Tế Của CodeGraph
Tree-sitter + SQLite FTS5

CodeGraph hoàn toàn không dùng LLM hay vector database. Nó dùng bộ parser WASM Tree-sitter siêu nhẹ (0 token) và lưu đồ thị vào SQLite local.

Cơ Hội Của Personal-KB
Unified Spec & Code Fabric

Hợp nhất Spec nghiệp vụ [HR-M04] với AST Code Symbols thật. Tạo ra liên kết 2 chiều mà cả CodeGraph lẫn Vector RAG độc lập đều không làm được.

1. Giải Phẫu Cơ Chế Cốt Lõi Của CodeGraph (Under The Hood)

Dữ liệu phân tích trực tiếp từ mã nguồn thực thi: @colbymchenry/codegraph-darwin-arm64/lib/dist/

Qua quá trình dịch ngược và phân tích mã thực thi trong gói Volta của hệ thống, CodeGraph hoạt động theo chu trình 4 giai đoạn hoàn toàn tất định (Deterministic, Zero-LLM):

BƯỚC 1: AST EXTRACTION
web-tree-sitter (WASM)

Quét file nguồn với 30+ ngữ pháp WASM (typescript, python, go, rust, dart...). Trích xuất 22 loại Nodes (functions, classes, interfaces...) với toạ độ startLine, endLine, docstring, signature.

BƯỚC 2: TWO-PASS LINKING
Resolution Engine

Pass 1 ghi nhận unresolvedReferences. Pass 2 chạy import-resolver.js, name-matcher.js, path-aliases.js để phân giải liên kết thành các Edge: calls, contains, imports, extends.

BƯỚC 3: PERSISTENCE
SQLite + FTS5 Index

Lưu toàn bộ vào .codegraph/codegraph.db. Bảng nodes, edges, files kèm virtual table nodes_fts cho phép tìm kiếm full-text biểu tượng siêu tốc không tốn bộ nhớ vector.

BƯỚC 4: GRAPH TRAVERSAL
Graph Queries & MCP

Cung cấp 8 công cụ MCP (codegraph_callers, codegraph_impact, codegraph_explore...) thông qua thuật toán duyệt đồ thị BFS/DFS trên SQL JOIN có composite index.

CẤU TRÚC DATABASE SQLITE THỰC TẾ CỦA CODEGRAPH (SCHEMA.SQL) Zero Vector Overhead 
-- 1. Bảng Nodes (Chứa mọi symbol khai báo trong code)
CREATE TABLE nodes (
    id TEXT PRIMARY KEY,               -- hash(file_path + qualified_name)
    kind TEXT NOT NULL,                -- function, class, method, interface...
    name TEXT NOT NULL, qualified_name TEXT NOT NULL,
    file_path TEXT NOT NULL, language TEXT NOT NULL,
    start_line INTEGER NOT NULL, end_line INTEGER NOT NULL,
    docstring TEXT, signature TEXT, visibility TEXT,
    is_exported INTEGER, is_async INTEGER, return_type TEXT
);

-- 2. Bảng Edges (Chứa quan hệ tĩnh giữa các code symbols)
CREATE TABLE edges (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source TEXT NOT NULL, target TEXT NOT NULL,
    kind TEXT NOT NULL,                -- calls, contains, imports, extends...
    line INTEGER, col INTEGER, provenance TEXT
);

-- 3. Chỉ mục Tìm kiếm Full-Text Lexical (FTS5)
CREATE VIRTUAL TABLE nodes_fts USING fts5(id, name, qualified_name, docstring, signature);

3. Bản Thiết Kế Kiến Trúc: Tích Hợp CodeGraph Subsystem Vào Personal-KB

Phương án tối ưu để Personal-KB hấp thụ toàn bộ sức mạnh của CodeGraph

Trong tài liệu kiến trúc [CYBEROS-01], Personal-KB đã quy định rõ 3 Cổng lưu trữ độc lập của Memory Fabric: DocumentStore, VectorStore, và GraphStore. Hiện tại, GraphStore của chúng ta chỉ mới định nghĩa các thực thể nghiệp vụ: Spec, Feature, Database_Table, API_Endpoint, Role.

KIẾN TRÚC HỢP NHẤT ĐỀ XUẤT (UNIFIED CODE & COGNITIVE FABRIC)
+-----------------------------------------------------------------------------------------+ | AI AGENT INTERFACE | | 1 Cổng Giao Tiếp MCP Duy Nhất: personal-kb | +-----------------------------------------------------------------------------------------+ | +-------------------------+-------------------------+ | | [Nghiệp Vụ & Quy Định] [Mã Nguồn Cú Pháp] query_cognitive_memory() query_code_symbol() recall_guardrails() trace_code_callers() verify_citation() trace_symbol_impact() | | +-------------------------------------+ +-------------------------------------+ | COGNITIVE MEMORY LAYER | | CODE GRAPH SUBSYSTEM | | (DocumentStore & VectorStore) | | (Tree-sitter WASM / Python) | | - Specs Markdown (HR-M04, PKB-01) | | - AST Nodes (Function, Class) | | - Negative Constraints (Gotchas) | | - Call Graph (Callers/Callees) | | - Dense Vectors (BGE-M3 / Qdrant) | | - Exact Line Numbers & Files | +-------------------------------------+ +-------------------------------------+ \ / \ / +-----------------------+-----------------------+ | [THE UNIFIED LINK BRIDGE] Spec [HR-M04] <=======> lockTimesheet() Feature: payroll_lock ==> TimesheetCronJob.execute() | PostgreSQL 17 / Local SQLite Cache

Lợi ích vượt trội khi Personal-KB hấp thụ CodeGraph:

  • Giảm độ phân mảnh cấu hình: Agent không cần cấu hình 2-3 MCP servers rời rạc. Chỉ cần 1 server personal-kb.
  • Truy nguyên ngược từ Code về Spec (Traceability): Khi Agent sửa hàm calculate_tax(), KB lập tức cảnh báo: *"Hàm này đang hiện thực quy định tại [HR-M05] §4.2, hãy tuân thủ Negative Constraint cấm dùng float"*. CodeGraph đơn lẻ không bao giờ biết được điều này!
  • Tiết kiệm 100% Token Ingestion: Quá trình index mã nguồn vẫn dùng Tree-sitter (0 token cost, tốc độ chớp nhoáng), không làm tốn chi phí embedding của hệ thống.
